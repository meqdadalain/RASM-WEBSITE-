# 14 — Dashboard

## Purpose

The Dashboard provides an executive overview of the engineering analysis.

It summarizes the project health before users inspect individual issues.

---

# Objectives

The dashboard should communicate:

- Overall quality
- Engineering risks
- Analysis completion
- Estimated impact

within a few seconds.

---

# KPI Cards

The MVP includes:

- Engineering Score
- Critical Issues
- Warnings
- Components Checked
- Estimated Savings
- Project Readiness

---

# Engineering Score

The score is not arbitrary.

It is calculated from:

- issue severity
- issue count
- rule coverage

The score breakdown must remain explainable.

---

# Analysis Progress

The analysis follows predefined stages.

Reading Geometry

↓

Recognizing Components

↓

Checking Standards

↓

Running Engineering Rules

↓

Generating Report

↓

Complete

---

# Risk Distribution

Issues are grouped by severity.

Critical

High

Medium

Low

---

# Savings

Savings displayed in the MVP are illustrative.

They must always be labeled:

"Illustrative demo scenario."

---

# Deferred

Not included

- Historical analytics
- Multi-project comparison
- CO₂ metrics
- Team productivity
- Financial forecasting

---

# Design Principle

The dashboard should answer one question:

"Is this project ready for construction?"
