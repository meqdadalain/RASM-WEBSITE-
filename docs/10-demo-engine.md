# 10 — Demo Engine

## Purpose

The Demo Engine defines the complete demonstration experience for RASM.

Its purpose is not to simulate every product capability.

Its purpose is to convince an industrial customer that RASM can identify engineering issues faster, more consistently, and more clearly than a traditional design review.

The entire experience should last approximately 5 to 10 minutes.

---

# Demo Objectives

At the end of the demonstration, the customer should answer "yes" to the following questions:

- Does RASM understand my type of industrial facility?
- Can it detect engineering issues?
- Can I easily locate issues in 3D?
- Can I understand why each issue matters?
- Can I share the results with my engineering team?

---

```
Home
```

---

# Step 1 — Home

Objectives:

- explain the product
- create confidence
- introduce the industrial model
- invite the user to launch the demonstration

Primary CTA:

Launch Demo

---

# Step 2 — AI Initialization

Animated sequence.

Example stages:

- Initializing AI Engine
- Loading Engineering Knowledge
- Preparing Geometry
- Connecting Rule Library

Duration:

5–10 seconds.

Purpose:

Create anticipation while preparing the workspace.

---

# Step 3 — Model Loading

Load one curated industrial GLB model.

Display:

- project name
- number of components
- disciplines detected
- engineering standards

---

# Step 4 — Analysis Progress

Show the engineering workflow.

Stages:

1. Reading Geometry
2. Recognizing Equipment
3. Building Component Graph
4. Detecting Clashes
5. Checking Standards
6. Evaluating Accessibility
7. Calculating Risk
8. Building Engineering Report

Each step displays progress.

---

# Step 5 — Dashboard

Display:

- Engineering Score
- Critical Issues
- Major Issues
- Minor Issues
- Estimated Cost Impact
- Estimated Time Savings
- Project Readiness

All values are clearly identified as demonstration data.

---

# Step 6 — Issue Review

Main workspace.

Layout:

- 3D Viewer
- Issue List
- Issue Details
- Dashboard
- Analysis Progress

Selecting an issue:

- highlights affected components
- moves camera
- displays engineering explanation

---

# Step 7 — AI Assistant

Purpose:

Explain issues using engineering language.

Typical questions:

- Why is this critical?
- Which standard is violated?
- What is the recommended correction?
- What are the project risks?

The MVP uses predefined engineering responses.

---

# Step 8 — Engineering Report

Generate a report including:

- Executive Summary
- Engineering KPIs
- Issue List
- Risk Assessment
- Recommendations
- Methodology
- Rules Applied

Export as PDF.

---

# Step 9 — Pilot Call To Action

Final screen.

Invite the customer to:

- Book a Pilot
- Request Analysis
- Contact RASM

The objective is to transform interest into a commercial discussion.

---

# Demo Success Criteria

A successful demonstration results in at least one of the following:

- request for a pilot
- request to analyze a customer model
- follow-up meeting
- investor interest

The Demo Engine is therefore the primary commercial tool of the MVP.
